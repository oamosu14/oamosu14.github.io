SentinelOps: Enterprise Infrastructure Simulation Platform

SentinelOps is a multi-site virtual infrastructure environment designed to simulate real-world enterprise operations across SRE, DevOps, and Cybersecurity domains using Linux-based systems.

The goal is not to build tools in isolation, but to model how production systems behave under monitoring, automation, logging, and security enforcement layers.

1. Problem Statement

Modern infrastructure teams operate across fragmented systems: monitoring tools, logging pipelines, automation frameworks, and security controls often exist in silos.

SentinelOps was built to unify these domains into a single operational simulation environment.

2. System Architecture

Multi-site topology:
  • IND-DC → Monitoring, API, Logging
  • FSH-DC → CI/CD, Dev, Test, Prod
  • MCV-DC → Web, Auth, Database
Core stack:
  • Prometheus → Metrics collection
  • Grafana → Visualization
  • Alertmanager → Incident routing
  • Rsyslog → Centralized logging
  • Ansible → Automation
  • UFW + Fail2Ban → Security enforcement

3. Observability Layer (SRE Design)

Metrics are collected using Node Exporter and aggregated in Prometheus. Grafana dashboards provide visibility into: CPU, memory, disk usage, and service health. Alertmanager handles threshold-based anomaly detection.

4. Logging & Visibility

All nodes forward logs to a centralized rsyslog aggregation system. This enables:
  • Cross-node log correlation
  • Incident traceability
  • Security event visibility

5. Automation Layer (Ansible)

Ansible is used to enforce configuration consistency across all nodes. Capabilities:
  • System configuration management
  • Package standardization
  • Security policy enforcement

6. Security Architecture

Security controls implemented:
  • SSH key-based authentication
  • Root login disabled
  • Firewall rules (UFW)
  • Fail2Ban brute-force protection
This simulates enterprise-grade access control enforcement.

7. CMDB / Inventory System

A lightweight CMDB was built using PHP + SQLite to track infrastructure assets. Features:
  • Node inventory tracking
  • IP mapping
  • Role-based classification
  • Auto-refresh dashboard (60s)

8. Incident Simulation

Controlled failure scenarios were introduced to validate system behavior:
  • Alert generation via Prometheus rules
  • Log correlation across rsyslog layer
  • Service recovery validation via SSH
This simulates real-world SRE incident response workflows.

9. Engineering Outcomes

This project demonstrates:
  • Distributed infrastructure design
  • SRE observability implementation
  • Cybersecurity enforcement architecture
  • Automation-driven operations model
